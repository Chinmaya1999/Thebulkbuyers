# The Bulk Buyers — Garments & Apparel B2B Marketplace

**React (Vite) · Node/Express · PostgreSQL** — retail (B2C) *and* wholesale (B2B) in one catalogue.

```
client/   React SPA (react-router, three.js 3D hero, role dashboards)
server/   Express API  (routes/, schema.sql, seed/, test/)
```

## Storefront
Luxury-editorial B2B wholesale experience (palette `#F8F7F4 · #171717 · #B88A55`, Cormorant Garamond + Inter; tokens at the top of `client/src/styles/lux.css`), built with React, react-router and Framer Motion:
- **Header:** announcement bar · intelligent search (products by name/SKU/brand, categories, brands, manufacturers) · account / wishlist / cart · category bar with **mega menu** (types, featured collections, popular products)
- **Home:** editorial hero · 16 discovery tiles · featured collections carousels (new, trending, best sellers, premium, seasonal, bulk deals) · wholesale advantages · manufacturers · CTA
- **Listing:** sidebar filters (category, subcategory, gender, age, brand, manufacturer, price, MOQ, stock, colour, size, fabric/material, GST, discount), grid/list, sorting, infinite scroll, skeletons, quick view, quick-add MOQ pack
- **Product:** gallery with zoom/lightbox · **size × colour bulk matrix** with live tier price, bulk discount, GST, MOQ + stock validation · add to cart / buy in bulk / request quotation / download spec sheet · accordions (fabric, specs, size guide, shipping, returns) · related + frequently-bought-together
- **Cart & checkout:** variant-grouped cart priced by the server (`POST /api/cart/price`), business info + GSTIN, billing/shipping addresses, shipping & payment method, order summary
- **Customer dashboard:** overview, orders, order tracking, quotations, invoices (print/PDF), wishlist, saved products, reorder, addresses, business profile, GST details, account settings
- Mobile: search overlay, category drawer, filter drawer, bottom navigation, sticky add-to-cart bar

### Pricing rules (server: `server/pricing.js`)
Quantities are summed **per product across all variants**. At/above the product's MOQ the wholesale tier applies (MOQ → max price, 2×MOQ → midpoint, 5×MOQ → min price); below MOQ the retail price applies. GST is added per product at its `gst_rate`. Stock (`stock_qty`, 0 = made to order) is enforced and decremented at checkout.
Payments: pay on delivery or bank transfer are *recorded*; no online gateway is integrated.

## Catalogue structure
Three levels, seeded from `server/seed/taxonomy.js` (edit that file or use Admin → Categories):
**Group** (Garment & Apparel · Fashion & Lifestyle) → **Category** (Men's, Women's, Kids & Baby, Sportswear, Innerwear & Sleepwear, Winter, Ethnic, Uniforms & Workwear, Footwear, Fashion Accessories) → **Product type** (281, e.g. "Polo T-Shirts", "Chelsea Boots").
Browse at `/categories` (the index) or filter `/shop?cat=…&sub=…&gender=…&age=…&season=…`.
Every product carries: name, SKU (auto `TBB-CAT-00001`), brand, gender, age group, category, product type, sizes, colours, fabric, pattern, fit, season, HSN code, GST rate, wholesale price range, retail (selling) price, purchase price *(private to the seller/admin)*, stock quantity *(0 = made to order)*, barcode.
Existing databases migrate automatically on startup (old 8 categories → new hierarchy).

## Roles — everything is run by the admin
- **Buyer** – the only self-service sign-up: shop, checkout, post RFQs, accept quotes, track orders, wishlist
- **Admin** – runs the whole platform from `/dashboard`:
  - **Orders** – create, reprice, change status, add tracking/AWB, record payment, delete
  - **Quotation requests** – raise RFQs for buyers, add quotes on behalf of suppliers, accept & convert to orders
  - **Products / Categories** – full create/edit/delete (all attributes, photos, stock, supplier, publish/hide, feature)
  - **Users & suppliers** – create/edit/suspend/delete buyers, suppliers, agents and admins; reset passwords
  - **Payments** – collections per order, supplier payouts, agent commissions
  - **Website content** – announcement bar, homepage hero, contact details, About text, footer (`GET /api/site`)
  - **Inquiries & Settings** – commissions, shipping & return policy
- **Suppliers (manufacturers) and agents** are records the admin manages; they no longer sign in (`/api/seller` and `/api/agent` were removed).

## Local development
Requires Node 20+ and a PostgreSQL database.

```bash
createdb bulkbuyers
cp .env.example .env            # set DATABASE_URL
npm install && npm --prefix client install
npm run dev                     # API :3000  +  React dev server http://localhost:5173
```
The schema is created automatically on boot. In development, demo data is seeded:
`buyer@demo.com`, `seller@demo.com`, `agent@demo.com` (password `Demo@12345`) and admin `admin@thebulkbuyers.com` / `Admin@12345`.

Or run everything with Docker: `docker compose up --build` → http://localhost:3000

## Production
```bash
npm run build      # builds client/dist
NODE_ENV=production DATABASE_URL=… ADMIN_EMAIL=… ADMIN_PASSWORD=… npm start
```
Express serves the API **and** the built React app from one process. Product photo uploads are stored in Postgres, so no persistent disk is needed.
- **Render**: `render.yaml` provisions the web service + Postgres.
- **Railway / Fly / any Docker host**: use the `Dockerfile` and set `DATABASE_URL` (+ `DATABASE_SSL=true` if your provider requires it).
- Serve over HTTPS (auth cookies are `Secure` in production). `SEED_DEMO` stays `false`.

## Security
- **Authentication:** bcrypt passwords, signed httpOnly `SameSite=Lax` cookie (7 days, `Secure` in production). Changing or admin-resetting a password revokes every other session. 5 failed logins lock the account for 15 minutes (`MAX_LOGIN_FAILS`). Suspending a user signs them out immediately. Self-registration only creates buyers.
- **Authorization:** role checks on every route (anonymous → 401, wrong role → 403); buyers can only read or change their own RFQs, orders, addresses and wishlist; admin cannot delete, demote or suspend themselves or remove the last admin.
- **CSRF:** unsafe requests whose `Origin` is cross-site are rejected (add trusted origins with `ALLOWED_ORIGINS`).
- **Audit trail:** every admin write is logged (`GET /api/admin/audit`).
- Rate limits: `API_LIMIT` (300/min), `LOGIN_LIMIT` (25/15 min), `REGISTER_LIMIT` (20/h) per IP.

## Tests
34 integration tests: auth rules, a role × endpoint authorization matrix, session revocation, lockout, token forgery, CSRF, data isolation between buyers, every admin option (users, products, categories, RFQs/quotes, orders, payments, inquiries, settings, website content, uploads), checkout and input robustness.
Start the API with raised limits, then run:
```bash
API_LIMIT=5000 LOGIN_LIMIT=1000 REGISTER_LIMIT=1000 PORT=3100 node server/server.js
BASE=http://localhost:3100 npm test
```
Tests create a few throw-away records in the dev database; use a development database only.
